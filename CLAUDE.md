# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`marinek.store` — одностраничный лендинг марафона похудения для женщин (укр. язык) + юридические страницы + страница «дякуємо» после оплаты. Next.js 14 (App Router), TypeScript, Tailwind CSS.

**Критично: сайт полностью статический (`output: 'export'` в [next.config.mjs](next.config.mjs))**. Это значит:
- Next.js API-роуты (`route.ts`) **не работают** — сервера нет вообще, всё собирается в статические файлы в `out/`.
- Любая серверная логика (webhook-и, проверка платежей, генерация чего-либо на лету) должна жить **вне** этого Next.js-приложения — например, как Netlify Functions в том же Netlify-сайте (см. ниже).
- `images: { unoptimized: true }` — нет серверной оптимизации картинок, все фото заранее сжаты в WebP (`public/images/`).

## Хостинг и деплой

- **Netlify** ([netlify.toml](netlify.toml)): `command = "npm run build"`, `publish = "out"`.
- Значения `NEXT_PUBLIC_*` вшиваются в билд на этапе сборки — после смены env-переменных нужен **ребилд**, а не просто рестарт.
- Домен: `marinek.store`.

## Оплата и выдача доступа (переделано 25.07.2026)

До этого доступ раздавался одной статичной ссылкой на всех, вшитой в клиентский бандл: `/thank-you?plan=X` открывался кем угодно без оплаты, а инвайт расходился пересылкой. Сейчас платёж создаётся на нашей стороне, подтверждается подписанным вебхуком, и только после этого выпускается персональный одноразовый инвайт.

**Готовые «платіжні кнопки» WayForPay удалены** из кабинета — они не позволяли задать свой `orderReference`, то есть связать платёж с человеком. Вместо них Purchase API: поля собираются и подписываются на сервере, клиент сабмитит форму на `secure.wayforpay.com/pay`.

Поток целиком:

```
Tariffs.tsx → PayButton → POST /api/create-payment
   ↓ (создаётся заказ pending, цена из СЕРВЕРНОГО прайса)
форма → secure.wayforpay.com/pay
   ↓ оплата
serviceUrl → /api/wayforpay-callback   (проверка подписи → paid → инвайт → письмо)
returnUrl  → /api/payment-return/<токен> → 303 → /thank-you/?t=<токен>
   ↓
/thank-you опрашивает /api/get-invite и показывает ссылку
```

Функции в [netlify/functions/](netlify/functions/), общий код в [netlify/lib/](netlify/lib/). Next.js API-роуты не работают — сайт статический.

### Грабли, на которые уже наступили

**Цена только с сервера** ([netlify/lib/plans.ts](netlify/lib/plans.ts)). Если брать из тела запроса, можно оплатить `personal` за 1 единицу валюты.

**Сумму сверять с заказом даже при валидной подписи.** Подпись подтверждает лишь то, что запрос от WayForPay.

**Вебхук обязан быть идемпотентным.** WayForPay ретраит до 4 суток, пока не получит подписанный `accept`. Без замка каждый ретрай выпускал бы новый действующий инвайт — в `issueInvite` для этого условный UPDATE по `invite_issued_at`.

**Отвечать `accept` даже если Telegram или почта упали** — иначе вебхук ходит днями. Заказ останется `paid` без `invite_link`, это видно в базе.

**Токен возврата — В ПУТИ, не в query.** WayForPay режет query-строку у `returnUrl`; проверено живым платежом — женщина видела нашу же страницу «Сторінку не знайдено», то есть запрос доходил, а `?t=` исчезал. Плюс WayForPay возвращает браузер **методом POST**, а Netlify на POST к статике отдаёт 404 — поэтому возврат принимает функция и делает 303 (этот статус превращает POST в GET).

**Логи функций Netlify через CLI приходят с пустым сообщением** — видно только время и `INFO`. Диагностировать ими не выйдет, не тратьте время.

## Telegram — три тарифа, ДВА канала

```
standard          → TG_CHANNEL_STANDARD_ID   «МАРАФОН СХУДНЕННЯ WITH MARINEK 💪»
chat, personal    → TG_CHANNEL_PREMIUM_ID    «VIP СХУДНЕННЯ WITH MARINEK💪»
```

Инвайты выпускаются `createChatInviteLink` с `member_limit: 1` и сроком 7 дней — ссылка умирает после первого входа. `member_limit` и `creates_join_request` взаимоисключающие, поэтому прежние «Заявки на вступ» больше не используются.

Бот `@marinek_marathon_bot` — админ в обоих каналах **только с правом «Додавати підписників»** (`can_invite_users`). Больше прав не давать: токен лежит в env, и утечка не должна давать возможность снести канал.

**Возврат денег гасит инвайт** (`Refunded`/`Voided` → `revokeChatInviteLink`). Ограничение: если женщина уже вошла в канал, отзыв ссылки её оттуда не выгоняет — для этого нужно знать её Telegram-аккаунт, то есть подписка на `chat_member` и хранение участников. Пока такие случаи разбираются вручную.

Ссылка на `/thank-you` показывается тремя слоями: кнопка на `https://t.me/+HASH`, вариант `tg://join?invite=HASH` для случая, когда домен `t.me` заблокирован, и текст с кнопкой «скопіювати». Дублируется письмом через Resend — единственная страховка, если вкладку закрыли.

## Структура

```
src/
  app/            # роуты (App Router): /, /oferta, /privacy, /rules, /thank-you, /payment-failed
  components/     # секции лендинга, LegalLayout, CookieConsent, ThankYouCard, PayButton
  lib/site.ts     # START_DATE, GA, RESULTS — БЕЗ цен и инвайтов, они на сервере
netlify/
  functions/      # create-payment, wayforpay-callback, get-invite,
                  # payment-return, reissue-invite
```

Всё, что попадает в `src/`, видно в исходниках страницы. Цены, платёжные ссылки и инвайты живут только в `netlify/` — именно через `src/lib/site.ts` они раньше и утекали.

Дата старта потока («03.08») — одна константа `START_DATE` в `src/lib/site.ts`, встречается в hero, тарифах, финальном CTA и sticky CTA. Дата переносилась уже дважды — меняется только здесь, по всему сайту подтянется само.

## Где остановились — работа поставлена на паузу 25.07.2026, возврат 08.08.2026

### Что работает и проверено живыми платежами

Оплата, проверка подписи, выдача одноразового инвайта, письмо, отклонение платежа, возврат денег и гашение инвайта при возврате. Тестовые платежи возвращены, база чистая. Инфраструктура на аккаунтах **Марины**, не разработчика: Netlify (`marinekfit` / сайт `marinek`), Supabase (проект `marinek-store`, ref `cdkexaplxybsldondifk`), Resend с подтверждённым доменом, бот в Telegram.

### Открытые хвосты — с них начинать

**1. Старые статичные инвайты в каналах — проверить, что отозваны.** Это главный незакрытый пункт: пока ссылки `+GOuTJufFE8g0MTVi` (Стандарт) и `+NNvTmwwDb1YzZmNi` (VIP) живы, в каналы пускают бесплатно, и половина смысла переделки теряется. Марина сказала, что отозвала, но **программно это не проверяется**: у бота нет метода для чужих ссылок, а страница `t.me` отдаёт одинаковый ответ и для живой, и для мёртвой, и даже для выдуманной. Единственная надёжная проверка — открыть ссылку с аккаунта, которого нет в канале.

**2. Возврат на страницу после оплаты — исход неизвестен.** Токен перенесён в путь `returnUrl`, на проде проверено curl-ом для POST, GET и запасного пути по `orderReference`. Но что реально увидела женщина после последнего платежа, никто не сказал. Если снова «Не знайшли ваше замовлення» — значит WayForPay режет и путь, и тогда единственный вариант: сделать письмо основным каналом выдачи, а страницу нейтральной.

**3. Минуты сборки Netlify исчерпаны** (300/мес на бесплатном тарифе). Коммит `2686862` с кнопками «вернуться назад» на экранах ошибки собран локально, но не выкачен. Квота сбрасывается в дату биллингового цикла. Собирать реже: не делать `netlify deploy --build` на каждую гипотезу.

**4. Этап 2 — админка `/admin`, не начата.** Функция перевыпуска [reissue-invite](netlify/functions/reissue-invite.ts) уже написана и задеплоена (гасит старую ссылку, проверяет JWT). Осталось: RLS-политика на `select` для `authenticated`, статическая страница со входом через Supabase Auth, аккаунт для Марины (создаётся через Admin API секретным ключом), таблица заказов с фильтрами и экспортом. Миграции придётся отдавать SQL-текстом на вставку в SQL Editor: MCP-подключение организацию Марины не видит.

**5. `/payment-failed` осиротела.** Ни одна ссылка на неё не ведёт, `declinedUrl` мы не передаём — `/thank-you` сама показывает отказ. Комментарий в файле утверждает обратное. Удалить или хотя бы поправить комментарий.

**6. Адрес ФОП в футере на каждой странице.** Марина просила убрать; решили не трогать, потому что закон «Про електронну комерцію» (ст. 7) требует доступа к местонахождению продавца, и эквайер обычно тоже. Компромисс, если вернётся к этому: оставить только в оферте, из футера убрать — доступ сохранится, а из поисковой выдачи почти уйдёт.
